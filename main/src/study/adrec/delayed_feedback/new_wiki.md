# 예측기 랜딩 과제 정리

## 1. DFM/DFOM 통합 (next dfm/dfom)

> 목표: 배치 DFM(PURCHASE)과 온라인 DFOM(APP·PF·MEM)이 따로 돌고 있는 것을 **하나의 스트리밍 모델**로 덮는다. 제안 형식은 "현행에 수학적·기술적 문제 A가 있고, 방법 B는 A'로 A를 없애므로 실험할 가치가 있다"로 통일한다.

### 1.1 출발점 — 두 모델은 같은 양을 다른 근사로 추정한다

두 모델이 최소화하려는 것은 같다. 진짜 분포 $p$ 에서의 기대 손실이다.

$$
\mathcal L(\theta) = \mathbb E_{(x,y)\sim p}\big[\ell(x, y; f_\theta(x))\big]
$$

그런데 스트림에서는 라벨이 늦게 와서 $p$ 로 뽑을 수 없다. 두 모델은 각자 다른 우회로를 쓴다.

| | 배치 DFM (`mtldfm_v2`) | 온라인 DFOM (`_fnw`) |
|---|---|---|
| 우회 방법 | 지연 분포를 지수분포로 **가정**해 미전환의 우도를 $1 - p + p\,e^{-\lambda d}$ 로 씀 | 클릭 즉시 0으로 넣고 전환 시 1 복사본을 추가한 뒤 **중요도 가중치** $p/q$ 로 되돌림 |
| 신선도 | 4시간 배치, 20일 창 | 30분 스트림 |
| 편향의 출처 | 지수분포 가정이 틀린 만큼 | 가중치 안의 $p$ 를 모델 자기 출력 $\hat p$ 로 대체한 만큼, 그리고 $q(x) \approx p(x)$ 근사 |

같은 목표를 향해 한쪽은 **분포 가정**으로, 다른 쪽은 **자기참조 가중치**로 간다. 아래 세 문제는 이 두 우회로에서 나온다.

### 1.2 문제 A → 방법 B → A'

**A1. 온라인 가중치가 모델 자기 출력이다.** FNW의 가중치는 양성 $1 + \hat p$, 음성 $(1 - \hat p)(1 + \hat p)$ 이고 $\hat p$ 는 지금 학습 중인 모델의 출력이다. 그래디언트가 0이 되는 지점이 $\hat p = p$ 하나라는 것은 증명돼 있지만, 그 과정은 자기참조다. 모델이 틀린 상태에서는 가중치도 틀리고, 신규 그룹처럼 모델이 아직 틀린 구간에서 특히 불리하다.

- **B1 = ES-DFM.** 대기 창 $e$ 를 두고, 가중치를 **확정 로그로 따로 학습한 분류기** $f_{dp}$(창 뒤 전환 확률), $f_{rn}$(관측 음성이 진짜 음성일 확률)로 만든다. 양성 $1 + f_{dp}$, 음성 $(1 + f_{dp})\,f_{rn}$.
- **A1'.** 가중치가 CVR 모델과 분리되어 자기참조 고리가 끊어지고, 두 인수가 모두 $[0,1]$ 확률이라 값이 유계다. FNW는 $e = 0$ 인 특수해이므로 현행에서 잃는 것이 없다. 대기 창 안에 오는 전환은 처음부터 1로 들어가 가짜 음성의 양 자체도 줄어든다.

**A2. 전환한 클릭만 두 번 들어가 $q(x) \ne p(x)$.** 중요도 가중치의 정확한 식은 $\frac{p(x)}{q(x)} \cdot \frac{p(y \mid x)}{q(v \mid x)}$ 인데, FNW와 ES-DFM은 앞 인수를 1로 **근사**한다. 실제로는 산 사람의 피처가 스트림에 더 자주 등장하므로 그만큼의 편향이 남고, 끝까지 안 산 클릭은 "확실히 0"이라는 정보가 학습에 한 번도 들어오지 않는다.

- **B2 = DEFER.** 어트리뷰션 창이 지나면 **모든 클릭**을 확정 라벨로 한 번 더 넣는다.
- **A2'.** 모든 클릭이 정확히 두 줄이 되어 $q(x) = p(x)$ 가 근사가 아니라 **등식**이 된다. 앞 인수가 사실로 1이 되고, 진짜 음성 정보가 처음으로 모델에 들어온다. 대가는 데이터 2배와 어트리뷰션 창만큼의 지연이다. 1일 창(vcvr)에서 이득이 크고 7일 창에서는 확인이 필요하다(DEFUSE 논문 표: Criteo-1d에서 ES-DFM보다 우세, 30d에서 열세).

**A3. 배치 DFM은 지연을 지수분포로 가정한다.** 미전환 항 $\log(1 - p + p\,e^{-\lambda d})$ 를 $p$ 로 미분하면 크기가 $F(d) = 1 - e^{-\lambda d}$ 에 비례한다. 가정이 맞아도 최근 클릭의 기울기는 거의 0이고($\lambda = 0.7/\text{일}$ 이면 2시간 전 클릭은 5.6%), 신규 그룹은 데이터가 전부 최근이라 자기 데이터로 스스로를 교정하지 못한다. 가정이 틀리면 그 위에 편향이 얹힌다. 게다가 이 손실은 스트림에서 수렴하지 못한다(ES-DFM 논문: Criteo NLL 1.26으로 발산).

- **B3 = DEFUSE (ES-DFM·DEFER 위에).** 관측 음성 하나를 "가짜 음성일 확률 $z$"와 "진짜 음성일 확률 $1 - z$"로 쪼개 양성 항과 음성 항에 동시에 넣는다. $z = 1 - f_{rn}$ 으로 별도 분류기에서 나온다.
- **A3'.** 지연 분포에 대한 **파라메트릭 가정이 없다.** "창 뒤 전환인가"를 분류기가 직접 맞히므로 $p(h > e)$ 를 따로 모델링하지 않는다. 미전환 샘플이 침묵하지 않고 $z$ 만큼 양성 방향 기울기를 즉시 낸다. 이상적 $z$ 아래 손실이 진짜 라벨 손실과 기댓값이 같다(점근 불편).

### 1.3 통합의 논리

세 방법은 같은 대기 창 스트림 위에 쌓인다. ES-DFM이 창과 보조 헤드를 깔고, DEFER가 재투입 대상을 넓히고, DEFUSE가 음성 항을 쪼갠다. 이 셋을 얹은 스트리밍 모델은 배치 DFM이 하던 일(지연 보정과 불편 추정)을 **지연 분포 가정 없이, 30분 신선도로** 한다. 그래서 PURCHASE를 배치에서 스트림으로 옮길 근거가 생기고, 네 라인이 한 모델이 된다.

근거가 있는 부분과 확인해야 하는 부분을 갈라 둔다.

| | 근거 |
|---|---|
| 배치 DFM 손실은 스트림에서 무너진다 | ES-DFM 논문 표 (DFM Criteo NLL 1.26, Vanilla 0.40) |
| 스트림 방법이 NLL 간격을 메운다 | ES-DFM R-NLL 0.68 (Criteo), DEFER RI-NLL 96.6%, DEFUSE RI-AUC 52.3% |
| Alibaba가 2026년에도 ES-DFM 가중치를 골격으로 쓴다 | TESLA (WWW 2026) 식 (1)·(2), 부록 C |
| **7일 창에서 스트림 방법이 배치 DFM만큼 되는가** | 논문 없음. 우리 데이터로 확인 |

### 1.4 통합 시 맞춰야 할 구조 차이

`torch-dnn_dfm_dfom.md`에 정리된 차이다. 통합 모델이 전부 흡수해야 한다.

| 항목 | 배치 DFM | 온라인 DFOM | 통합 시 |
|---|---|---|---|
| 헤드 | action_type별 $K$개 + $\lambda$ 헤드, `output_mask`로 합산 | 단일 (MEM은 MTL) | action_type별 헤드 유지, $\lambda$ 헤드 → $f_{dp}$·$f_{rn}$ 헤드로 교체 |
| 후처리 | `conv_multiplier` (mpc) | 없음 | 유지 여부 결정 |
| 어트리뷰션 창 | 7일 | 7일 (vcvr 1일) | DEFER 재투입 시점 = 창 |
| 데이터 | parquet 20일 | Sequoia 스트림 | 스트림 + 재투입 경로 |
| 복수 전환 | 미지원 | 미지원 (넥슨 사례, CVR 350%) | 별도 판단 |

### 1.5 실험 설계

셋이 같은 스트림을 쓰므로 **오프라인 스트리밍 재생으로 한 번에 비교**하고 승자만 온라인 A/B로 올린다.

| 팔 | 내용 |
|---|---|
| 대조군 | 현행 `_fnw` ($e = 0$) |
| A | ES-DFM |
| B | + DEFER 재투입 |
| C | + DEFUSE $z$ |
| D | B + C |
| 참조 | 배치 DFM (PURCHASE 라인에서만) |

지표는 성숙 구간 RIG·캘리브레이션(제약)과 신규 그룹 $N$ 곡선(목적)이다. 온라인은 팔을 둘 이하로 줄인다. 신규 그룹이 목표 지표라 팔이 늘면 표본이 부족하다.

### 2.1 unknown index — 신규 그룹이 매칭되는 행은 시간에 따라 둘이다

`nn.Embedding`은 광고그룹 ID 하나에 행 하나가 대응하는 임베딩 테이블이다. 신규 그룹이 매칭되는 행은 하나가 아니라 **시간에 따라 둘**이다.

**1단계 — 1번 행.** 신규 그룹은 처음에 자기 행이 없다. 인덱서에 등록되기 전이라 **모든 신규 그룹이 1번 행(unknown index) 하나를 같이 쓴다.** 이 행은 비어 있지 않다. 신규 그룹 전체의 트래픽으로 학습되어 "신규 그룹 평균" 벡터가 되어 있다. 이전 CTR 실험(ADRECALG-3660·3860)이 건드린 것이 이 행이다. 1번 행을 학습된 값 대신 전체 행의 (가중) 평균으로 갈아 끼웠고, 결과가 지면마다 갈렸다.

**2단계 — 자기 행.** 인덱서가 그 그룹에 번호를 주면 그때 자기 행이 생기는데, **이 행이 "아무 학습된 수치가 없는 행"**이다. $N(0, 10^{-5})$ 로 시작한다. 그 순간 그룹은 학습된 1번 행에서 빈 자기 행으로 옮겨가고, 이 점프가 회의 메모의 과대예측이다. **이전 실험은 이 행을 건드리지 않았다.**

| | 이전 CTR 실험 | 이번 제안 |
|---|---|---|
| 건드리는 행 | 1번 행 (공유) | 자기 행 (2단계) + 필요하면 1번 행도 |
| 채우는 값 | 전체 행의 가중 평균 | **같은 계정·캠페인 형제 그룹 행의 평균** |
| 왜 다른가 | 모든 신규 그룹에 같은 벡터 → 광고주 간 CVR 차이를 못 담음 | 그 광고주의 다른 그룹들 값 → CVR 수준이 비슷할 가능성 높음 |

이전 실험은 "효과가 없었다"가 아니라 **지면과 피처마다 부호가 갈렸다.** tb는 −30%로 크게 좋아졌고 daum·network는 +6% 나빠졌다. 전체 평균 하나로 모두를 덮으니 맞는 곳과 틀리는 곳이 갈린 것이고, 그게 조건을 붙여야 한다는 근거다.

한 줄로 하면, **"빈 행을 전체 평균으로 채우면 반은 맞고 반은 틀리니, 그 그룹의 형제들 평균으로 채우자"**가 제안이고, 거기에 **"1번 행에서 빈 행으로 점프하는 시점 자체를 없애자"**를 더한 것이 고도화다.

### 2.2 두 단계가 동작하는 코드 (torch-dnn)

#### 1단계 — 신규 그룹이 1번 행을 공유하며 학습하는 경로

**(a) 사전에 없는 ID는 1번** — `utils/vocab.py` 483~485행

```python
output_vocab[k][None] = 0   # 값 없음 → 0번
output_vocab[k][0] = 0
output_vocab[k][-1] = 1     # 모르는 값(-1) → 1번  ← unknown
```

배치 라인이 인덱스 파일을 읽을 때 이 세 줄로 예약 자리를 박는다. 온라인 라인은 Sequoia가 같은 규약으로 인덱스를 매겨 보낸다. 신규 그룹은 여기서 전부 1번이 된다.

**(b) 1번 행은 보통 행처럼 학습** — `models/model/feature.py` 208~214행

```python
self.embed = nn.Embedding(self.input_dim + 1, self.output_dim, padding_idx=feature_config.get("padding_idx"))
torch.nn.init.normal_(self.embed.weight, RN_MEAN, RN_STDDEV)   # 전 행 N(0, 1e-5)
self.embed._fill_padding_idx_with_zero()                       # 0번 행만 0 고정

def forward(self, input):
    return self.embed(input)                                   # 1번이 들어오면 1번 행이 나가고, 역전파도 1번 행에 쌓임
```

`padding_idx`는 0이라 0번만 학습에서 빠진다. 1번을 막는 코드는 없다. 신규 그룹 클릭이 전부 1번으로 들어오므로 1번 행은 신규 그룹 전체의 평균을 배우게 된다.

**(c) run이 바뀌어도 1번 행은 그대로 이어짐** — `utils_online/export.py` `inject_old_to_new`

```python
if "embed" in key and len(shape_before) == 2 and shape_before[0] != shape_after[0]:
    _resize_emb_layer_size(...)          # 테이블 크기가 바뀐 경우 → 2단계
else:  # just copy as before
    value.index_copy_(0, torch.arange(len(old_trainer["state_dict"][key])), old_trainer["state_dict"][key])
```

30분마다 새 run이 뜰 때 이전 모델의 행을 그대로 복사한다. 1번 행도 여기 포함되어 계속 누적 학습된다.

#### 2단계 — 자기 번호를 받은 그룹이 빈 행에서 시작하는 경로

**(a) 테이블이 커지면 늘어난 행은 빈 값** — `utils_online/export.py` `_resize_emb_layer_size`

```python
value.data = torch.nn.Parameter(torch.randn(shape_after))
torch.nn.init.normal_(value.data, RN_MEAN, RN_STDDEV)         # ① 새 테이블 전체를 N(0, 1e-5)로

key_length = min(len(old_trainer["state_dict"][key]), len(value))
index = torch.arange(key_length)
new_value = value * (1 - forget)
value.index_copy_(0, index, new_value[:key_length])
value.index_add_(0, index, old_trainer["state_dict"][key][:key_length], alpha=forget)   # ② 기존 행만 덮어씀
```

인덱서가 신규 그룹에 번호를 주어 상한이 올라가면 이 함수가 돈다. 새 테이블을 전부 $N(0, 10^{-5})$ 로 만들고(①), 기존 번호 범위만 이전 값으로 덮는다(②). **늘어난 꼬리 부분, 즉 방금 번호를 받은 그룹들의 행은 ①의 값 그대로 남는다.** `forget`은 기존 행을 얼마나 물려받을지의 비율이라 새 행과는 무관하다.

이 순간 그 그룹은 학습된 1번 행에서 이 빈 행으로 옮겨진다. 회의 메모의 과대예측 지점이다.

**(b) 은퇴한 번호를 재사용할 때도 빈 값** — `utils_online/export.py` `cleaning_inactive_embed`

```python
not_used = feat_info.get("inactive_values", [])              # 인덱서가 알려준 비활성 번호
...
value[idx] = torch.randn_like(value[idx]) * RN_STDDEV        # 그 행을 N(0, 1e-5)로 리셋
optimizer.state[value]["exp_avg"].index_fill_(feat_dim, idx, 0.0)      # Adam 1차 모멘트 0
optimizer.state[value]["exp_avg_sq"].index_fill_(feat_dim, idx, 0.0)   # Adam 2차 모멘트 0
```

테이블을 늘리지 않고 안 쓰는 번호를 새 그룹에 재배정하는 경우다. 값만 아니라 옵티마이저 상태까지 0으로 밀어서, 새 그룹은 완전한 백지에서 시작한다.

#### 제안이 손댈 자리

| 단계 | 코드 | 지금 | 바꿀 것 |
|---|---|---|---|
| 1 | `feature.py` 1번 행 | 신규 그룹 전체 평균 | 이전 CTR 실험이 여기를 가중 평균으로 교체 |
| 2-a | `_resize_emb_layer_size` ① | 새 행 $N(0, 10^{-5})$ | **형제 그룹 평균**으로 채움 |
| 2-b | `cleaning_inactive_embed` | 재사용 행 리셋 | 같은 값으로 채움. 빠뜨리면 재사용 슬롯을 받은 그룹만 여전히 백지 |

2-a와 2-b는 같은 함수를 호출하게 묶으면 된다. 두 곳 모두 "이 번호가 어느 계정·캠페인의 그룹인가"를 알아야 하므로, 형제 평균을 계산하려면 그룹→계정 매핑을 run 시점에 조회할 수 있어야 한다. 이 부분이 구현의 핵심 의존성이다.

### 2.3 현재 상태 진단

신규 광고그룹은 두 단계를 거친다. 회의의 "unknown index를 모든 신규 광고그룹이 쓴다"와 "신규가 아니게 되는 시점에 학습이 덜 된 임베딩을 써서 과대예측"이 각각 이 두 단계다.

| 단계 | 상태 | 임베딩 | 코드 근거 |
|---|---|---|---|
| **A. unknown** | 인덱서에 group_id가 없음 | 인덱스 1(`<unk>`) 행. **모든 신규 그룹이 공유**하고 그 트래픽으로 계속 학습되는 행 | `utils/vocab.py` (0 = null, 1 = unk), `sequoia_dataset._count_index` |
| **B. 자기 인덱스 직후** | 인덱서가 id를 추가 | 새 행 $N(0, 10^{-5})$. 은퇴 슬롯 재사용이면 randn·1e-5 + Adam 모멘트 0 | `export._resize_emb_layer_size`, `cleaning_inactive_embed` |

- 단계 A의 unknown 행은 사실상 **"신규 그룹 평균"을 학습한 벡터**다. 단계 B로 넘어가는 순간 그 벡터에서 0 근처 벡터로 **점프**하고, 그 뒤 며칠간 자기 데이터로 채워진다. 두 단계는 원인이 달라 처방도 다르다. 이전 CTR 실험은 A만, wiki.md의 C4 제안은 B만 다뤘다.
- 배치 DFM(PURCHASE)은 run마다 vocab을 다시 만들고, `build_vocab_v4`가 group_id·image_hash 인덱스별 **최초 등장 시각**(`coldstart_dttm`)을 기록한다. "신규 광고그룹을 무엇으로 정의하나"에 바로 쓸 수 있는 필드다. 노출 수가 `TAIL_CUT_TRESHOLD` 미만인 id는 vocab에서 빠져 unknown에 머문다.
- 온라인은 `count_special_index`가 run마다 인덱스 0·1 비율을 로그로 남긴다. **unknown 트래픽 비율은 지금도 측정된다.**
- 캘리브레이터: torch-dnn에는 FNC 보정(`forward_recalibration`, 미사용)과 캘리브레이션 범위 체크(0.3~3.0 벗어나면 예외)만 있다. 회의에서 말한 서빙 측 캘리브레이터는 위치 확인 필요.

### 2.4 이전 CTR 실험(ADRECALG-3660·3860)에서 배울 것

| 시점 | 방법 | 결과 |
|---|---|---|
| 2025.11 오프라인 | unknown 행을 전체 행 **단순 평균**으로 교체 | 과예측 **악화** (+29%). 노출 적은 미학습 행들이 평균을 오염 |
| 2025.12 오프라인 | 최근 10분 bimp 비중 **가중 평균** | slot unknown lift 74.7% → 12%, group_id 17% → −0.2% (network) |
| 2026.01 온라인 3일 | 가중 평균, 4피처 | 전체 −12.4% 개선. account_id −46% |
| 2026.02 온라인 7일 | 같음 | 전체 **+4.4% 악화**. tb −30%·criteo −6% 개선 / daum·network +6% 악화 / slot +181% 악화 / group_id +4.9% 악화 |

교훈 셋.
1. **전역 평균은 지면·피처마다 부호가 갈린다.** "지금 트래픽의 평균 광고"가 "신규 그룹의 기대값"과 다르기 때문이다.
2. **3일 → 7일로 가며 효과가 사라졌다.** 고정 벡터로 교체하면 그 뒤 학습이 진행돼도 unknown 행은 낡는다.
3. **account_id 조건이 붙은 구간이 가장 크게 개선됐다**(중간 −46%). 계정 정보가 신호를 갖는다는 증거이고, 아래 형제 그룹 평균의 근거다.

단순 평균 코드는 torch-dnn 태그 `ADRECALG-3660-1`에 `replace_unknown_with_mean`(`utils_online/export.py`)으로 남아 있고 main에는 없다. 설정 키는 `mean_embedding.init_with_mean_embedding`, `replace_unknown_with_mean_embedding`, `unknown_index_features`. **가중 평균 버전은 torch-dnn 어느 ref에도 없다.**

### 2.5 고도화 방향

**핵심 주장.** 이전 실험의 실패 원인은 평균을 낸 것이 아니라 **조건 없이** 평균을 낸 것이다. 광고주 간 CVR은 몇 배씩 다르므로 전역 평균은 모두를 같은 값으로 회귀시킨다. 같은 계정·캠페인의 형제 그룹 평균은 그 광고주의 CVR 수준을 담는다. 이것은 신규 광고 CVR을 광고주·캠페인 계층의 과거 성과로 추정한 Lee et al. (KDD 2012)의 임베딩판이다.

- **단계 B 처방 (초기 제안 2번).** 새 행의 초기값을 **같은 계정·캠페인 형제 그룹 임베딩의 평균**으로. 형제가 없으면 계정 → 캠페인 목적 → 전역 순 폴백. 형제도 최근성·노출로 가중.
- **단계 A 처방.** 회의의 "unknown 대신 형제 임베딩을 그때그때 계산"과 같은 뜻이다. 구현이 둘로 갈린다.
  - (i) 서빙·학습 시 lookup으로 형제 평균을 계산해 unknown 자리에 주입. 이전 실험 코드의 연장.
  - (ii) **모델 구조로 흡수** — 그룹 임베딩을 `계정 임베딩 + 그룹 잔차`로 두는 계층 임베딩. unknown 그룹은 잔차가 0이라 자동으로 계정 값으로 떨어지고, 자기 인덱스를 받아도 잔차만 새로 배우므로 단계 A·B가 한 구조로 풀린다. 점프가 사라진다.
- **대상 한정.** 이전 실험에서 slot은 어떤 방법으로도 악화됐다. group_id(필요시 account_id)로 한정한다.
- **캘리브레이터와의 관계.** 서빙 캘리브레이터가 그룹별 실측/예측 비율을 곱하는 방식이면 신규 그룹은 실측이 없어 캘리브레이터도 도울 수 없는 구간이고, 초기화는 그 앞단이다. 겹친다면 캘리브레이터가 계정 단위 prior를 쓰는 경우인데, 위치 확인 후 판단.

### 2.6 문헌 지도 — 초기값을 어디서 가져오나

| 출처 | 방법 | 핵심 | 우리 적용 |
|---|---|---|---|
| 계층 통계 | Lee, Orten, Dasdan, Li (KDD 2012, Turn) — https://doi.org/10.1145/2339530.2339651 | 신규 광고 CVR을 광고주·캠페인 계층의 과거 성과로 추정. **형제 평균의 원형** | 2.3의 논리적 근거 |
| 속성 → 생성기 | MetaEmb (Pan et al., SIGIR 2019) — https://arxiv.org/abs/1904.11547 | 속성으로 초기 임베딩을 생성하는 생성기를 메타러닝. CVR에도 적용 | 생성기 학습 파이프라인 추가 필요. 3단계 |
| 이웃 광고 | GME (SIGIR 2021) — https://arxiv.org/abs/2105.08909 | 새 광고와 기존 광고를 그래프로 연결해 이웃에서 초기 임베딩 증류 | 형제 평균을 학습된 가중으로 일반화한 것 |

| 구조 변경 | EmerG (Baidu, KDD 2024) — https://arxiv.org/abs/2407.10112 | 속성으로 아이템별 피처 상호작용 그래프 생성. 임베딩이 아니라 네트워크를 바꿈 | 범위 밖 |
| 스트리밍 | PAM (Kuaishou, KDD 2025) — https://arxiv.org/abs/2411.11225 | 스트리밍에서 인기도 구간별 메타러닝. **온라인 학습 제약을 명시적으로 다룬 유일한 것** | 온라인 라인 참고 |

공수 대비 순서는 계층 통계 → 형제 평균 → MWUF다. 생성기·그래프·구조 변경은 학습 파이프라인이 늘어난다.

### 2.7 실험 설계

1. **신규 정의 고정** — 배치는 `coldstart_dttm`, 온라인은 인덱스 1(unknown) 또는 인덱스 부여 시각. 회의의 "데이터를 가지고 기준을 정한다"에 해당.
2. **단계 A·B를 나눠 측정** — 그룹 생성 후 경과 시간별 캘리브레이션 오차 곡선을 초기화 방식별로 겹쳐 그린다. 첫 몇 시간(A)과 인덱스 부여 직후(B)의 점프를 따로 본다.
3. **오프라인** — 이전 실험과 같은 ONNX 재추론과 리플레이. 초기화 변형: 현행 / 전역 가중 평균(이전 실험 재현) / 계정 형제 평균 / 계정+캠페인 형제 평균.
4. **온라인** — 지면 하나로 A/B. 이전 실험이 7일에 효과가 뒤집혔으므로 최소 2주.
5. **구현 지점** — 모델 생성 시점 `torch.nn.init.normal_`, `export.py` 슬롯 재사용 경로, `cmd/reset_embed.py` 세 곳. 옵티마이저 모멘트 0 상태에서 출발값만 커지면 초반 갱신 동역학이 바뀌는 점 확인.

### 2.8 확인 필요

- 2025.12 **가중 평균 구현 코드**의 위치 (torch-dnn에는 단순 평균만 남음)
- 회의의 **캘리브레이터**가 무엇이고 어디 있는지
- **인덱서 갱신 주기** — 새 group_id에 인덱스가 붙는 시점을 정하는 외부 작업. 단계 A의 길이가 여기에 달림

### 초기 제안 내용
**의미 있는 값으로 초기화하면 초기 pCVR 안정에 도움이 될 수 있다.** 초기값 후보는 아래 순서로 본다.

| | 초기값 | 평가 |
|---|---|---|
| 1 | 전역 group_id 임베딩 평균 | 사실상 무효 — 지금도 예측이 "평균적인 그룹" 값이라 달라지는 게 없다 |
| 2 | **같은 계정·캠페인 형제 그룹 임베딩의 평균** | 싸고 정보가 있다. 형제가 없으면 계정 → 목적 순으로 폴백. **첫 실험감** |
| 3 | 속성(계정·캠페인·목적·소재)을 받아 임베딩을 생성하는 모델 | MetaEmb 방식. 가장 강하지만 학습 파이프라인이 하나 늘어난다 |

**구현 시 주의 두 가지.** ① 초기화 지점이 한 곳이 아니다 — 모델 생성 시점의 `torch.nn.init.normal_` 외에 `utils_online/export.py`의 슬롯 재사용 경로(`reset not used embedding`)와 `cmd/reset_embed.py`도 같이 고쳐야 한다. 안 그러면 은퇴한 슬롯을 물려받은 새 그룹은 여전히 $10^{-5}$ 로 시작한다. ② 옵티마이저 모멘트를 0으로 민 상태에서 출발값만 커지면 초반 갱신 동역학이 바뀐다.

**측정**: 초기화 방식별로 그룹 생성 후 경과 시간별 캘리브레이션 오차 곡선을 겹쳐 그린다. 첫 몇 시간 구간의 차이가 C4의 크기다.
