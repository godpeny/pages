# 특화 혹은 스페셜 혹은 개별 사양의 기준은 무엇이 되는것인가? - 작년 테무나 이번 참여형 광고 건처럼 맞춤형 대응이나 개발해주는 기준에 대한 얘기

## 광고추천모델 플랫폼에서 개별 사양 판단 기준

| 항목 | 레퍼런스 | 레퍼런스 내용 |
|---|---|---|
| **1. 특정 광고주에게만 적용되는 코드·모델이 생김** | Sculley et al., *Hidden Technical Debt in Machine Learning Systems* (NIPS 2015) | ML 시스템의 위험 요인을 경계 침식, 엔탱글먼트, 숨은 피드백 루프, 미신고 소비자, 데이터 의존성, 설정 이슈, 시스템 수준 안티패턴으로 분류. glue code, pipeline jungles, dead experimental codepaths가 개별 사양이 남기는 부채의 이름. 숨은 부채는 조용히 복리로 늘어나 위험하며, 전략적으로 부채를 질 수는 있어도 모든 부채는 상환해야 한다는 프레이밍. |
| | AWS Well-Architected SaaS Lens — *Multi-tenant microservices* | 서비스가 테넌트 컨텍스트를 참조·적용해야 하지만, **개발자가 코드에 테넌트 인식을 도입해야 하는 정도를 제한하는 것이 목표**. 테넌트별 처리는 라이브러리·모듈·공유 구성물로 밀어넣어 정책과 메커니즘을 감춰야 한다. `if (advertiser_id == X)` 금지의 규범적 근거. |
| | AWS APN Blog — *Tenant Onboarding Best Practices* | SaaS 비즈니스는 **일회성 요구사항을 지원하는 상황을 피하기 위해** 운영의 모든 측면을 자동화한다. |
| **2. 광고주별 KPI·라벨·타깃 정의를 별도 사용** | Montero-Manso & Hyndman, *Principles and Algorithms for Forecasting Groups of Time Series: Locality and Globality* (IJF 2021) | 전역 방법은 국소 방법보다 더 제한적이지 않고, 계열 간 유사성 가정 없이도 양쪽이 동일한 예측을 낼 수 있다. 국소 방법의 복잡도는 집합 크기에 따라 커지지만 전역 방법은 일정하게 유지된다. → 분리는 표현력을 얻는 게 아니라 추정 편의를 얻고 복잡도를 지불하는 거래. |
| | Zinkevich, *Rules of Machine Learning* (Google) | Rule #7: 휴리스틱을 피처로 바꾸거나 외부에서 처리하라. Rule #2: 메트릭 설계·구현을 먼저 하라. Rule #4: 첫 모델은 단순하게, 인프라를 제대로. Rule #8: 시스템의 신선도 요구를 파악하라 — 광고 서빙은 매일 새 광고가 들어와 일 단위 갱신이 필요하다는 예시. |
| | Sheng et al., *STAR: One Model to Serve All* (CIKM 2021) | 공유 네트워크를 전체 데이터로 학습하고 도메인별 파라미터를 특성에 맞게 적응. 알리바바 디스플레이 광고에 2020년 말 배포, CTR 8%·RPM 6% 개선. 분리 대신 공유+조건화가 작동한 실증. |
| **3. 광고주 전용 데이터 파이프라인·API 연동** | AWS SaaS Lens — *Core Isolation* (silo / pool / bridge) | 테넌트가 자원을 공유하는 pool, 분리하는 silo, 일부는 silo·일부는 pool인 혼합 형태 bridge. "어디까지 공유하고 어디서 격리하는가"의 표준 어휘. 격리 수준을 가격 티어에 매핑하는 논의 포함. |
| | Sculley et al. (동일) | pipeline jungles — 파이프라인이 개별 대응으로 증식하며 관리 불가능해지는 안티패턴. |
| **4. 공통 로직과 다른 입찰·랭킹·탐색 정책** | Deng et al., *Towards Efficient Auctions in an Auto-bidding World* (WWW 2021) | 부스트를 인센티브 호환적으로 도입해 부스트가 큰 낙찰자가 지불액은 오히려 줄어들게 설계하고, 광고주 가치·광고 품질·판매자 비용을 결합한 정량 지표로 부스트를 구성. 예외 규칙이 아니라 원칙 있는 메커니즘으로 흡수하는 템플릿. |
| | Alimohammadi, Mehta, Perlroth, *Incentive Compatibility in the Auto-bidding World* | 예산·tCPA 제약 모두에서 FPA·SPA가 auto-bidding IC가 아니며, truthful·scale-invariant·symmetric한 어떤 경매도 AIC가 아니다. 대칭성을 깨는 개별 조정에 대한 반대 논거. |
| **5. 별도 학습·배포·모니터링·장애 대응 필요** | Breck, Cai, Nielsen, Salib, Sculley, *The ML Test Score* (IEEE Big Data 2017) | 프로덕션 ML 경험에서 도출한 28개의 구체적 테스트·모니터링 항목을 제시, 프로덕션 준비도 개선과 ML 기술 부채 상환의 로드맵. **모델 하나 추가 = 28개 항목이 곱해짐**을 견적에 반영하는 근거. |
| | Standley et al., *Which Tasks Should Be Learned Together in Multi-task Learning?* (ICML 2020) | 태스크 관계가 학습 설정과 무관해야 하지만 실제로는 그렇지 않고, 네트워크 용량과 학습 데이터 양이 친화도에 영향을 주며, 더 유사한 태스크가 반드시 함께 학습하기에 더 좋지도 않고, 멀티태스크 친화도와 전이학습 친화도 사이에 상관이 없다. → 분리 여부는 사전 추론 불가, 측정으로만 확립. |
| | Crawshaw, *Multi-Task Learning with DNNs: A Survey* §4.1 | 태스크 그룹화는 negative transfer가 보이면 처음부터 학습을 분리하는 접근인데, 조합별 학습 시행착오에 상당한 계산 시간이 필요하고 brute force 없이 결합 학습 동역학을 정확히 판단할 방법은 거의 없다. |
| | negative transfer 원인 분해 | 표현 충돌, 데이터 불균형(큰 태스크가 그래디언트를 지배해 작은 태스크가 학습 신호를 굶음), 그래디언트 간섭. "전역 손실이 대형 세그먼트에 지배된다"의 일반형. |
| | Pinterest Eng., *Unifying Ads Engagement Modeling Across Pinterest Surfaces* (2026.03) | 분리돼 있던 두 모델을 하나로 통합하고 서피스별 캘리브레이션과 가벼운 특화 컴포넌트만 남김. 통합 동기가 성능이 아니라 반복 속도·비용·유지보수 문제였고, 단순 베이스라인 먼저·특화는 점진적으로라는 원칙을 명시. 결국 되돌리게 된다는 실증. |

크리에이티브 컨설팅
소재 성과 진단과 제작 가이드. 구체적으로는 해당 플랫폼에서 어떤 포맷·화면비·첫 3초 구성·카피 길이가 잘 작동하는지 자사 데이터 기반으로 제시하고, 크리에이티브 피로도(같은 소재의 CTR이 노출 누적에 따라 떨어지는 현상)를 진단해 교체 주기를 제안하고, A/B용 소재 세트를 설계합니다. 플랫폼에 따라 인하우스 스튜디오가 소재를 직접 제작해주기도 합니다.
