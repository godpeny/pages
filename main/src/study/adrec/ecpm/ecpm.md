# eCPM 이해하기
## 한 줄 요약

**eCPM은 "이 광고를 1,000번 노출하면 광고주에게 얼마를 받을 수 있을 것으로 기대되는가"** 입니다.
과금 방식이 서로 다른 광고(노출당, 클릭당, 구매당 …)를 하나의 경매에서 공정하게 비교하기 위해, 모두 "노출 1,000회당 기대 매출"이라는 같은 단위로 바꾼 값입니다.

| 과금 타입 | 언제 돈을 받나 | 필요한 예측값 | eCPM |
|---|---|---|---|
| CPM | Viewable 노출 1,000회 | pVR | `BA × pVR` |
| CPC (방문 목적) | 클릭 | pCTR | `BA × pCTR × 1000` |
| CPC (전환 목적) | 클릭 | pCTR, pCVR | `BAb(pCVR) × pCTR × 1000` |
| CPA | 구매 등 액션 | pCTR, pCVR | `BA × pCTR × pCVR × 1000` |
| CPV | 동영상 3초 재생 | pVPR | `BA × pVPR × 1000` |

아래에서 이 표의 각 단어가 무슨 뜻인지 차례로 설명합니다.

## 1. Player: 광고 한 번이 뜨기까지 누가 관여하나

| Player | 하는 일 | 카카오에서는 |
|---|---|---|
| **사용자** | 앱·웹에서 광고를 보고 누르는 사람 | |
| **매체 (Publisher)** | 광고가 실리는 앱·웹페이지. 광고 자리(지면)를 팔아 돈을 번다 | 카카오톡, 다음, 외부 제휴 앱 등 |
| **SSP** (Supply Side Platform) | 매체의 광고 자리를 대신 팔아 주는 플랫폼. 광고 자리가 생기면 여러 DSP에 "입찰하세요"라고 요청하고, 이긴 광고를 매체에 보내 준다. 트래픽(광고 자리)을 **공급**하므로 Supply | **AdFit** |
| **DSP** (Demand Side Platform) | 광고주의 예산과 광고를 받아, SSP의 입찰 요청에 응찰해서 광고를 내보내는 플랫폼. 트래픽을 **구매**하므로 Demand | **카카오모먼트 (Moment)** |
| **대행사** | 광고주 대신 DSP에서 광고를 운영해 주는 회사 | |
| **광고주** | 돈을 내고 사용자에게 광고를 보여주고 싶은 회사 | |

**예시: SSP와 DSP는 각자 누구 편인가**

30대 직장인이 출근길에 **A 뉴스 앱**을 열었고, 기사 하단에 광고 자리가 하나 생겼다고 해 봅시다.

- **SSP는 매체(A 뉴스 앱) 편**입니다. A 뉴스 앱은 광고주를 하나하나 찾아다닐 수 없으니 SSP에 자리 판매를 맡겨 두었습니다. SSP는 이 자리를 여러 DSP에 동시에 내놓고 "30대 남성, 서울, 출근 시간대 자리인데 얼마 내실래요?"라고 묻습니다. 목표는 **이 자리를 최대한 비싸게 파는 것**입니다.
- **DSP는 광고주 편**입니다. 운동화 브랜드 B, 대출 서비스 C, 게임 D가 각자 예산을 맡겨 두었습니다. 입찰 요청을 받은 DSP는 이 사용자에게 어떤 광고가 가장 가치 있을지 따져 봅니다. 예를 들어 "이 사람은 운동화 광고를 누를 확률이 높다"고 판단하면 B 광고로 응찰합니다. 목표는 **광고주 돈으로 좋은 자리를 적정한 값에 사는 것**입니다.
- 다른 DSP들도 각자의 광고로 응찰하고, SSP는 가장 높은 값을 부른 DSP의 광고를 A 뉴스 앱에 보냅니다. 사용자 화면에는 B의 운동화 광고가 뜹니다.

부동산에 비유하면 SSP는 **집주인 쪽 중개인**(비싸게 팔기), DSP는 **구매자 쪽 중개인**(싸고 좋은 집 사기)입니다. 매체와 광고주는 서로 직접 만나지 않고, 이 두 플랫폼이 매 노출마다 중간에서 거래를 성사시킵니다.

카카오는 **SSP(AdFit)와 DSP(Moment)를 둘 다** 운영합니다. 그래서 광고추천팀은 세 쪽을 동시에 신경 써야 합니다.

- 플랫폼(카카오)의 매출
- 매체의 수익
- 광고주의 효율

## 2. 돈의 흐름: 누가 누구에게 언제 돈을 주나

### 2.1 실시간 경매 (RTB)

광고 자리는 미리 팔리는 것이 아니라 **사용자가 화면을 여는 순간마다 경매**로 팔립니다. 이를 RTB(Real Time Bidding)라고 합니다.

```
사용자가 앱을 엶
  → 매체: "광고 자리 하나 있어요"            → SSP
  → SSP: "이 자리 얼마에 사실래요?" (입찰 요청) → 여러 DSP
  → 각 DSP: 자기 광고 중 1등을 골라 가격 제시 (입찰)
  → SSP: 가장 높은 가격을 낸 DSP 선정 (낙찰, win)
  → 낙찰된 광고가 사용자 화면에 노출
```

이 모든 과정이 수십~수백 ms 안에 끝납니다.

### 2.2 돈이 오가는 3단계 (CPC 광고 기준)

| 단계 | 누가 → 누구 | 언제 | 얼마 |
|---|---|---|---|
| (1) | 광고주 → DSP | **클릭이 났을 때만** | 광고주가 정한 클릭당 금액 (BA) |
| (2) | DSP → SSP | **경매에서 이기는 즉시** (클릭과 무관) | 낙찰가 |
| (3) | SSP → 매체 | 정산 시 | SSP 수수료를 뗀 금액 |

대행사가 끼는 경우에는 이렇게 됩니다.
- (1-1) 광고주는 예산만 정해서 대행사에 맡깁니다.
- (1-2) 대행사는 수수료를 뺀 예산으로 광고를 운영합니다.

### 2.3 여기서 생기는 문제 = eCPM이 필요한 이유

(1)과 (2)의 **시점과 단위가 다릅니다.**

- DSP는 경매에서 이길 때마다 SSP에 **노출 단위로** 돈을 냅니다.
- 그런데 CPC 광고주는 **클릭이 나야** 돈을 냅니다. 클릭이 안 나면 DSP는 SSP에 돈만 내고 한 푼도 못 받습니다.

그래서 DSP는 입찰하기 전에 **"이 노출에서 광고주에게 얼마를 받을 수 있을지"를 예측**해야 합니다. 그래야 SSP에 얼마까지 낼 수 있는지 정할 수 있습니다.

또 DSP 안에는 과금 방식이 다른 광고가 섞여 있습니다. 클릭당 500원짜리 광고와 구매당 2만 원짜리 광고 중 어느 것을 내보낼지 비교하려면 **같은 단위**가 필요합니다.

이 두 문제를 한 번에 푸는 값이 eCPM입니다.

## 3. 핵심 용어

### 3.1 광고 퍼널: 노출에서 전환까지

광고가 낙찰된 뒤 사용자 반응은 깔때기(퍼널)처럼 줄어듭니다.

```
win(낙찰) ──▶ viewable 노출 ──▶ 클릭 ──▶ 전환(구매 등)
                                   └──▶ (동영상) 3초 재생
```

**win이란?**

win은 **DSP가 SSP 경매에서 이긴 순간**입니다. "이 광고 자리는 모먼트 광고가 가져간다"고 정해진 시점이고, 아직 사용자가 광고를 본 것은 아닙니다.

```
사용자가 앱을 엶 → SSP가 경매를 엶 → 모먼트가 입찰
   ├─ 짐 (loss): 다른 DSP 광고가 나감. 여기서 끝
   └─ 이김 (win): 모먼트 광고가 사용자 기기로 전달됨
          ├─ 실제로 화면에 그려짐 (노출, bimp)
          │     └─ 광고의 50% 이상이 1초 이상 보임 (viewable 노출)
          │           └─ 클릭 → 전환
          └─ 화면에 못 그려짐 (앱 종료, 로딩 전 이탈 등)
```

| 단계 | 앞 단계보다 줄어드는 이유 |
|---|---|
| win | 경매에서 이겨야 시작됨 |
| viewable 노출 | 이겼어도 사용자가 앱을 닫거나, 스크롤로 금방 지나가거나, 광고가 화면 밖에 있으면 viewable이 안 됨 |
| 클릭 | 본 사람 중 일부만 누름 |
| 전환 | 누른 사람 중 일부만 구매 등을 함 |

예를 들어 광고 자리가 100번 생겼다면 이렇게 줄어듭니다(설명용 숫자).

| 단계 | 횟수 | 비율 |
|---|---|---|
| 입찰 | 100 | |
| **win** | **30** | 승률 30% |
| viewable 노출 | 18 | pVR = 18 / 30 = 60% |
| 클릭 | 0.3 | pCTR = 0.3 / 30 = 1% |
| 전환 | 0.006 | pCVR = 0.006 / 0.3 = 2% |

win이 중요한 이유는 **돈이 오가는 시점**이기 때문입니다. 위 에서 본 것처럼 DSP는 win 순간 SSP에 낙찰가를 냅니다. 사용자가 광고를 실제로 봤는지, 눌렀는지와는 상관없습니다. 반면 CPC 광고주는 클릭이 나야 돈을 냅니다. 그래서 DSP는 "이번 win 한 번에 돈을 내는데, 그 win에서 광고주에게 얼마를 받을 수 있나"를 계산해야 하고, 이것이 아래 표에서 pCTR·pVR의 분모가 win인 이유입니다.

**bimp란?**

bimp는 **낙찰된 광고가 사용자 화면에 실제로 그려진 노출(impression)** 입니다. win과 viewable 노출 사이에 있는 단계입니다.

| 이벤트 | 뜻 | 로그 테이블 (모먼트) |
|---|---|---|
| win | 경매에서 이김. 아직 화면에 안 그려졌을 수 있음 | `raw_km_filtered_win` |
| **bimp** | 광고가 화면에 그려짐 | `biz_adid.raw_km_filtered_bimp` |
| vimp (viewable 노출) | 그려진 광고의 50% 이상이 1초 이상 보임 | |

- 그래서 수는 항상 **win ≥ bimp ≥ vimp** 입니다. win 30번 중 앱을 바로 닫은 사용자가 있었다면 bimp는 28번처럼 더 적게 남습니다.
- 지표에서 "노출"이라고 하면 보통 bimp를 뜻합니다. 광고 로그 분석 가이드도 CTR = `click / bimp`, eCPM = `charge_amount / bimp × 1000`으로 정의합니다.

> **주의: 기준이 win에서 bimp로 바뀐 흐름이 있습니다.**
> 이 문서는 원 위키를 따라 "분모 = win"으로 적었습니다. 그런데 완료 프로젝트 "30. Win → Bimp 전환"과, "bimp 모델 전환 이후 pVR 캘리브레이션 알람이 늘었다"는 기록(241206 pVR 모델 캘리브레이션 대응)을 보면 일부 모델은 분모를 **bimp(실제로 화면에 그려진 노출)** 로 바꾼 것으로 보입니다. [광고 로그 분석 가이드](https://kakao.atlassian.net/wiki/spaces/adrec/pages/144493115)도 CTR을 `click / bimp`로 정의합니다. 어떤 모델이 어느 기준을 쓰는지는 모델별로 확인하세요.
>
> - **win**: 경매에서 이긴 것. DSP가 SSP에 돈을 내는 기준
> - **bimp**: 실제로 화면에 그려진 노출. 지금 지표·모델에서 노출 기준으로 더 많이 쓰임

각 단계로 넘어갈 확률을 모델이 예측합니다. 이름 앞의 **p**는 predicted(예측값)라는 뜻입니다.

| 예측값 | 정의 | 뜻 |
|---|---|---|
| **pVR** (Viewable Rate) | viewable 노출 / win | 낙찰된 광고가 제대로 보일 확률 |
| **pCTR** (Click Through Rate) | 클릭 / win | 낙찰된 광고를 누를 확률 |
| **pCVR** (Conversion Rate) | 전환 / 클릭 | 누른 사람이 구매 등을 할 확률 |
| **pVPR** (Video Play Rate) | 3초 재생 / win | 낙찰된 동영상이 3초 이상 재생될 확률 |

- **Viewable 노출**: 광고 이미지의 50% 이상이 1초 이상 화면에 보인 경우입니다. 낙찰됐다고 다 viewable은 아닙니다(스크롤로 금방 지나가는 경우 등).
- pCTR과 pVR의 분모가 모두 **win**이라는 점에 주의하세요. 그래서 CPC eCPM에는 pVR을 곱하지 않습니다(4.2 참고).
- 참고로 pCTR × pCVR = (클릭/win) × (전환/클릭) = **전환/win** 입니다. 이를 pAR이라고도 합니다.

### 3.2 CPM: "1,000회당 가격"이라는 단위

**CPM = Cost Per Mille**, mille은 라틴어로 1,000입니다. 광고 업계는 노출 1회당 가격이 너무 작아서(몇 원 단위) **1,000회 기준 가격**으로 이야기합니다.

- CPM 3,000원 = 노출 1,000회에 3,000원 = 노출 1회에 3원

CPM은 두 가지 의미로 쓰여서 헷갈리기 쉽습니다.
- **과금 타입으로서의 CPM**: "노출 1,000회마다 돈을 내겠다"는 광고 상품 (3.3)
- **가격 단위로서의 CPM**: 모든 가격을 1,000회 기준으로 표현하는 단위. eCPM의 "CPM"이 이쪽입니다.

### 3.3 과금 타입 (bid type): 광고주가 언제 돈을 내나

| 과금 타입 | 풀네임 | 광고주가 돈을 내는 때 | 비고 |
|---|---|---|---|
| **CPM** | Cost Per Mille | viewable 노출 1,000회 | 실제로는 viewable 노출 1회마다 BA/1000씩 과금. win 했다고 다 과금되지 않음 |
| **CPC** | Cost Per Click | 클릭 1회 | 가장 흔한 방식 |
| **CPA** | Cost Per Action | 구매·가입 등 액션 1회 | |
| **CPV** | Cost Per play View | 동영상 3초 재생 1회 | 성격상 CPC보다 동영상 광고의 CPM에 가까움 |
| **CPT** | Cost Per Time | 일정 시간 동안 자리를 통째로 삼 | 경매·예측이 필요 없음. A2(광고추천)를 거치지 않고 이데아에서 처리 |

### 3.4 BA, 입찰가, 낙찰가, 과금액: 네 가지 "가격"

광고 한 번에 여러 가격이 등장합니다. 이것부터 구분해 두면 나머지가 쉬워집니다.

| 용어 | 누가 정하나 | 뜻 |
|---|---|---|
| **BA** (Bid Amount) | 광고주(수동) 또는 시스템(자동입찰) | 광고주가 **과금 타입 단위로** 내기로 한 금액. 예: 클릭당 500원 |
| **eCPM** | DSP(광고추천) | BA를 노출 1,000회당 기대 매출로 환산한 값 |
| **bid price (입찰가)** | DSP | DSP가 SSP 경매에 실제로 써 내는 금액. eCPM에서 수수료·할인을 뺀 값 |
| **낙찰가 (win price)** | SSP 경매 | DSP가 SSP에 실제로 내는 금액. 보통 입찰가보다 낮음 (3.8) |
| **과금액 (charge)** | 결과 | 클릭 등이 실제로 발생해서 광고주 예산에서 빠지는 금액 |

## 4. eCPM 계산

### 4.1 기본 아이디어

$$
\text{eCPM} = \underbrace{\text{BA}}_{\text{이벤트 1회당 받을 돈}} \times \underbrace{\text{es}}_{\text{노출 1회당 그 이벤트가 날 확률}} \times 1000
$$

- **es** (estimation): 노출 1회당 과금 이벤트가 일어날 확률. 과금 타입마다 다릅니다.
- BA × es = 노출 1회에 기대되는 매출
- × 1000 = 1,000회 기준으로 단위 맞추기

즉 **e**CPM의 e는 expected(기대값)입니다. "광고주가 1,000회당 얼마를 내기로 했나"가 아니라 "확률을 고려하면 1,000회당 얼마를 받을 것으로 기대되나"입니다.

### 4.2 과금 타입별 계산과 예시

| 과금 타입 | es | eCPM | 예시 | 예시 eCPM |
|---|---|---|---|---|
| CPM | pVR | `BA × pVR` | BA 3,000원(1,000회당), pVR 0.6 | 1,800원 |
| CPC (방문) | pCTR | `BA × pCTR × 1000` | BA 500원, pCTR 1% | 5,000원 |
| CPA | pCTR × pCVR | `BA × pCTR × pCVR × 1000` | BA 20,000원, pCTR 1%, pCVR 2% | 4,000원 |
| CPV | pVPR | `BA × pVPR × 1000` | BA 50원, pVPR 5% | 2,500원 |

예시 숫자는 설명을 위해 만든 값입니다. 이 네 광고가 같은 자리를 두고 겨룬다면 eCPM이 가장 높은 **CPC 광고(5,000원)** 가 DSP 내부 1등이 됩니다. 클릭당 500원은 구매당 2만 원보다 훨씬 싸 보이지만, 확률까지 곱하면 기대 매출은 더 큽니다.

타입별로 짚을 점은 이렇습니다.
- **CPM에 ×1000이 없는 이유**: BA 자체가 이미 1,000회당 가격이기 때문입니다.
- **CPC에 pVR이 없는 이유**: 클릭은 viewable 여부와 상관없이 과금되고, pCTR의 분모가 이미 win이기 때문입니다.
- **CPA**: pCTR × pCVR은 "노출 1회가 결국 구매로 이어질 확률"입니다.

> 참고: Money Flow 위키에서는 모든 타입을 `ecpm = ba × es × 1000` 한 가지 식으로 표기합니다. CPM은 이 식에서 ba를 노출 1회 단위로 본 것으로 이해하면 두 위키가 맞아떨어집니다. 실제 구현은 [danke-bidding-logic-lib](https://github.daumkakao.com/adrec/danke-bidding-logic-lib)를 기준으로 확인하세요.

### 4.3 수동입찰과 자동입찰

BA를 누가 정하느냐에 따라 두 가지로 나뉩니다.

| | 수동입찰 (MANUAL) | 자동입찰 (AUTOBID) |
|---|---|---|
| BA를 정하는 쪽 | 광고주가 직접 입력 | 시스템이 요청마다 실시간으로 조절 |
| 광고주가 입력하는 것 | 클릭당·노출당 가격 등 | 예산, 또는 목표 CPC·CPA·ROAS |
| 장점 | 예측 가능 | 광고주 목적(클릭 수, 전환 수 최대화 등)에 맞춰 최적화 |

자동입찰에서 고를 수 있는 입찰전략은 이렇습니다. 자세한 내용은 [0. 자동입찰 소개](https://kakao.atlassian.net/wiki/x/0TBUC)를 참고하세요.

| 목적 | 입찰전략 | 내부 명칭 | 광고주 입력 |
|---|---|---|---|
| 방문 | 클릭수 최대화 | Maximize Click | 예산 |
| 방문 | CPC 비용목표 | Target CPC | CPC 입찰가 |
| 전환 | 전환수 최대화 | Maximize Conversion | 예산 |
| 전환 | CPA 비용목표 | Target CPA | CPA 입찰가 |
| 전환 | 전환가치 최대화 | Maximize Conversion Value | 예산 |
| 전환 | ROAS 목표 | Target ROAS | ROAS |

### 4.4 전환 목적 CPC: 클릭으로 과금하면서 전환을 노리는 방법

전환 목적 광고는 과금은 **클릭** 기준인데, 목표는 **전환**입니다. 이 차이를 BA를 조절해서 메웁니다.

- 전환 목적 광고는 **반드시 자동입찰**이라 시스템이 BA를 바꿀 수 있습니다.
- 사용자×광고 조합마다 pCVR을 예측하고,
  - pCVR이 평균보다 높으면(살 것 같은 사람) BA를 올리고,
  - 낮으면 BA를 내립니다.
- 이렇게 pCVR로 정한 BA를 `BAb(pCVR)`라고 씁니다(bidding function).

$$
\text{eCPM} = \text{BA}_b(\text{pCVR}) \times \text{pCTR} \times 1000
$$

결과적으로 같은 클릭이라도 **살 것 같은 사람의 클릭에는 더 비싸게 입찰**합니다.

실제 자동입찰 식은 여기에 몇 가지 장치가 더 붙습니다(Money Flow 위키 기준).

```
ba = min( conv_base_bid × (pCVR ^ pcvr_power) ^ pcvr_bid_power , max_ba )
es = pCTR ^ pctr_bid_power
```

| 파라미터 | 뜻 |
|---|---|
| base_bid / conv_base_bid | 자동입찰이 계산한 기준 입찰가 (클릭 기준 / 전환 기준) |
| *_power, *_bid_power | 예측값에 거듭제곱을 걸어 영향력을 조절하는 값 (예측기 버킷 / 자동입찰 버킷 단위) |
| max_ba | pCVR을 과하게 예측해서 예산을 너무 빨리 쓰는 것을 막는 상한 |
| pCVS | 전환가치(구매 금액) 예측값. 전환가치 최대화·ROAS 목표 광고에서 conv_base_bid에 곱해짐 |

## 5. 입찰: eCPM에서 실제 입찰가까지

eCPM은 **광고주에게 받을 것으로 기대되는 돈**입니다. 이 돈을 SSP에 다 낼 수는 없습니다. 중간에 대행사와 DSP의 몫을 떼야 하기 때문입니다.

### 5.1 DSP 안에서 쓰는 세 가지 점수

| 이름 | 용도 | 계산 (초기값) |
|---|---|---|
| **pcpm** (= eCPM) | 광고주 과금 기준 | `ba × alpha` |
| **rankScore (rs)** | DSP 안에서 1등 광고를 고르는 점수 | `ba × alpha × (1 − Ca)` |
| **strategicPrice (sp)** | SSP에 실제로 써 내는 입찰가 | `ba × alpha × (1 − Ca − Cd)` |

- `alpha = es × 1000` 입니다. 즉 `ba × alpha`가 곧 eCPM입니다.
- **Ca**: 대행사 수수료율. 직접 운영(OLS)이면 0%, 대행사면 15%.
- **Cd**: DSP 수수료율. 일괄 15%.

### 5.2 단계별 흐름

1. **초기 계산**: 모든 후보 광고의 pcpm, rs, sp를 계산합니다.
2. **랭킹**: rs 순으로 줄을 세워 후보를 좁힙니다(약 5,500개 → 50개).
3. **어뷰징 상한 (max eCPM)**: 어뷰징 체크에 걸린 트래픽이면 eCPM에 상한을 걸어 입찰가를 낮춥니다.
4. **actionLocation 보정**: 한 슬롯에 클릭 위치가 여러 개면, 첫 위치가 아닌 곳에 대해 SSP에 내는 가격을 깎습니다.
5. **Winner(bid shading)**: 마지막으로 입찰가를 할인합니다(5.4).

여기까지 거치면 SSP에 내는 최종 입찰가는 이렇습니다.

$$
\text{sp} = \text{ba} \times \text{alpha} \times (1 - C_a - C_d - \text{bsr})
$$

### 5.3 경매와 낙찰가

SSP는 가장 높은 입찰가를 낸 DSP를 고릅니다. 다만 이긴 DSP가 **자기가 써 낸 가격을 그대로 내지는 않습니다.**

- **Second price**: 2등의 입찰가만큼만 냅니다.
- **Bid floor**: 매체가 정한 최저가가 있으면, 그보다는 많이 내야 합니다.
- 그래서 실제 낙찰가는 보통 **max(2등 입찰가, bid floor)** 수준이 됩니다.

### 5.4 Bid shading: 입찰가를 일부러 깎기

DSP는 **이길 수 있는 선에서 입찰가를 낮추는** 전략도 씁니다. 일반적으로 써 낸 가격을 그대로 내는 경매(first price)에서는 입찰가가 곧 지불액이 되므로, 입찰가를 깎는 만큼 매체에 내는 돈을 아낄 수 있습니다. 이를 bid shading이라고 하며, PDM 모듈(Winner)이 할인율 **bsr**(BidShadingRate)을 예측합니다.

bsr은 두 부분으로 나뉩니다.

$$
\text{bsr} = \underbrace{\text{msr}}_{\text{광고주에게 돌려줌}} + \underbrace{\text{sr}}_{\text{DSP가 가짐}}
$$

| 구성 | 이름 | 뜻 |
|---|---|---|
| **msr** | MarginShareRate | 아낀 돈 중 **광고주에게 돌려주는** 비율. 실제 과금을 `ba × (1 − msr)`로 깎아 줌 |
| **sr** | SurplusRate | 아낀 돈 중 **DSP(광고추천)가 갖는** 비율 |

예를 들어 bsr = 0.5이고 margin share proportion이 50%면 msr = 0.25(광고주 몫), sr = 0.25(DSP 몫)입니다.

## 6. 마진과 Surplus: 중간 Player는 무엇으로 돈을 버나

예측이 정확하다고 가정하면, 돈을 내기만 하는 광고주와 받기만 하는 매체를 빼고 **중간 Player들은 어디서 돈을 버는가?**

### 6.1 Player별 마진

| Player | 돈을 버는 방법 |
|---|---|
| **SSP** | DSP에게 받은 낙찰가에서 **수수료를 떼고** 매체에 정산 |
| **대행사** | 광고주 과금액의 **15%를 모먼트가 대행사에 수수료로** 줌. 대행사는 예산을 많이 쓸수록 돈을 벌기 때문에 **예산 소진율**이 가장 중요함. 그래서 모먼트는 eCPM에서 15%(Ca)를 빼고 입찰해야 손해를 보지 않음 |
| **DSP** | ① **입찰가와 낙찰가의 차이**: second price·bid floor 덕분에 기대 과금액보다 적게 SSP에 냄<br>② **고정 마진**: eCPM 전부로 입찰하지 않고 처음부터 Cd(15%)를 뺌. 원 위키에서는 `eCPM_happy = eCPM − margin`으로 표현 |

### 6.2 DSP margin과 Surplus의 차이

이 두 용어가 가장 헷갈립니다(Money Flow 위키 FAQ 정리).

| | DSP margin | Surplus |
|---|---|---|
| 정의 | 광고주에게 받은 돈 − SSP에 낸 돈 | **매체 정산을 얼마나 아꼈는가** (bid shading 중 sr 몫) |
| 식 | `charge amount − win amount` | `eCPM(할인 전) × sr` |
| 과금과의 관계 | **실제 과금과 관련 있음** (클릭이 나야 생김) | **실제 과금과 무관** (입찰 시점에 정해짐) |
| 크기 | 항상 고정 마진 15% 이상을 목표로 함 | 15%를 넘는 추가 몫 |

- surplus가 늘면, 마진 프로토콜 적용 전보다 DSP margin이 **그만큼 늘어납니다.**
  `새 DSP margin = 기존 DSP margin + Surplus`
- 다만 트래픽 하나하나로 보면 sr과 DSP margin이 비례하지만, **전체 합으로 보면 surplus가 늘어도 DSP margin이 줄 수 있습니다.** DSP margin은 실제 클릭·전환이 나야 생기기 때문입니다.

### 6.3 숫자로 한 번에 보기

대행사를 통한 CPC 광고, 노출 1,000회 기준입니다. 숫자는 설명용 예시입니다.

| 항목 | 계산 | 금액 |
|---|---|---|
| BA | 광고주 설정 | 클릭당 500원 |
| pCTR | 모델 예측 | 1% |
| eCPM (pcpm) | 500 × 0.01 × 1000 | **5,000원** |
| rankScore | 5,000 × (1 − 0.15) | 4,250원 |
| strategicPrice (shading 전) | 5,000 × (1 − 0.15 − 0.15) | 3,500원 |
| 실제 낙찰가 (second price) | 2등이 3,000원이었다고 가정 | **3,000원** |

예측이 정확해서 1,000회 노출에 클릭이 10번 났다면, 돈은 이렇게 나뉩니다.

| 누가 | 금액 |
|---|---|
| 광고주가 낸 돈 | 500 × 10 = 5,000원 |
| → 대행사 수수료 (15%) | 750원 |
| → SSP에 낸 낙찰가 | 3,000원 (SSP는 여기서 수수료를 떼고 매체에 정산) |
| → DSP에 남는 돈 | 5,000 − 750 − 3,000 = **1,250원** |

- 6.2의 FAQ 정의(charge − win)로 DSP margin을 계산하면 5,000 − 3,000 = 2,000원입니다. 여기서 대행사에 줄 750원을 빼면 DSP 몫은 1,250원입니다.
- 1,250원은 고정 마진 750원(Cd 15%)과, second price 덕분에 아낀 500원(3,500 − 3,000)을 합친 금액입니다.
반대로 클릭이 예측보다 적게 났다면 DSP는 이미 3,000원을 냈는데 받을 돈이 줄어 손해를 봅니다. **예측(pCTR, pCVR)의 정확도가 곧 DSP의 수익**인 이유입니다.

## 7. 용어 사전

| 용어 | 뜻 |
|---|---|
| RTB | Real Time Bidding. 노출 기회마다 실시간 경매로 광고 자리를 파는 방식 |
| win | DSP가 SSP 경매에서 낙찰된 것. DSP가 SSP에 돈을 내는 시점이며, 아직 화면에 노출된 것은 아님 |
| loss | 경매에서 진 것. 다른 DSP 광고가 나감 |
| bimp | 낙찰된 광고가 실제로 화면에 그려진 노출. 지금 지표·모델에서 노출 기준으로 많이 쓰임 |
| viewable 노출 | 광고의 50% 이상이 1초 이상 보인 노출 |
| BA | Bid Amount. 광고주가 과금 타입 단위로 내기로 한 금액 |
| es | estimation. 노출 1회당 과금 이벤트 확률 |
| alpha | es × 1000 |
| eCPM / pcpm | 노출 1,000회당 기대 매출 = ba × alpha |
| rankScore | DSP 내부 랭킹 점수 = eCPM × (1 − Ca) |
| strategicPrice | SSP에 써 내는 입찰가 = eCPM × (1 − Ca − Cd − bsr) |
| Ca / Cd | 대행사 수수료율 / DSP 수수료율 |
| bsr / msr / sr | bid shading 할인율 / 그중 광고주 환원분 / 그중 DSP 몫(surplus) |
| bid floor | 매체가 정한 최저 낙찰가 |
| second price | 낙찰자가 2등 입찰가만큼만 내는 경매 방식 |
| max_ba | 자동입찰 BA 상한 |
| max eCPM | 어뷰징 트래픽에 거는 eCPM 상한 |
| OLS | 광고주가 대행사 없이 직접 운영하는 경우 (Ca = 0%) |
