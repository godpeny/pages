# WINNER는 어떻게 동작하나 (현재 기준)

## 1. 한 줄 요약

WINNER는 **"이번 경매에서 이기려면 최소 얼마를 내야 하는지" 예측해서, 딱 그만큼만 입찰하게 해 주는 모델**이에요.

모먼트가 광고 하나를 내보내기로 정하면, 그 광고가 낼 수 있는 최대 금액(eCPM)이 정해져요. 하지만 최대 금액을 그대로 내면 손해일 때가 많아요. 경쟁자들이 그보다 훨씬 낮게 불렀다면, 그 경쟁자들보다 조금만 높게 내도 이길 수 있기 때문이에요. WINNER가 그 "조금만 높게"를 정해요.

## 2. 비유로 이해하기

중고 경매에 참여한다고 생각해 보면 쉬워요.

- 나는 이 물건에 **최대 10,000원**까지 낼 의향이 있어요. → **eCPM**
- 다른 참가자들 중 가장 높게 부른 사람이 **5,100원**을 불렀어요. → **넘어야 할 가격** (WINNER가 예측하는 값)
- 그러면 나는 10,000원이 아니라 **5,100원 남짓**만 불러도 이겨요. → **최종 입찰가**
- 아낀 4,900원이 광고주의 비용 절감이에요.

문제는 **다른 참가자들이 얼마를 부를지 미리 알 수 없다**는 거예요. 그래서 과거 경매 기록을 보고 예측하는 모델이 필요하고, 그게 WINNER예요.

> 위키에는 이 "넘어야 할 가격"이 "Winning Price = XMAS 기준 타 DSP의 1등 가격"으로 적혀 있어요. 풀어 쓰면 **"카카오 SSP 경매에서 모먼트를 뺀 다른 광고 플랫폼들이 부른 가격 중 가장 높은 값"**이에요.

## 3. 전체 흐름에서 어디에 있나

```
① 모먼트 안에서 광고 후보들 비교 (eCPM으로 줄 세우기)
② 1등 광고 선정 → 이 광고의 최대 금액 = eCPM
③ WINNER: "얼마나 깎아도 이길까?" 결정        ← 여기
④ 최종 입찰가로 카카오 SSP(XMAS) 경매에 참가
⑤ 외부 광고 플랫폼들과 경쟁 → 가장 높은 쪽이 낙찰
```

WINNER는 **입찰가를 정하는 마지막 단계**예요.

## 4. 알아야 할 용어 (최소한만)

| 용어 | 쉬운 뜻 | 예시 (eCPM 10,000원) |
|---|---|---|
| **eCPM** | 이 광고가 낼 수 있는 최대 금액 | 10,000 |
| **수수료 (ca, cd)** | 대행사 몫(0% 또는 15%) + 모먼트 몫(기본 15%). 입찰 전에 먼저 떼요 | cd 15% → 1,500 |
| **eCPM'** | 수수료를 떼고 실제로 경매에 쓸 수 있는 돈 | 8,500 |
| **dr** (discount rate) | 쓸 수 있는 돈 중 실제로 내는 비율 | 5,100 / 8,500 = **0.6** |
| **bsr** (bid shading rate) | 원래 eCPM 대비 깎는 비율 | **0.34** (= 3,400 / 10,000) |
| **sp** (최종 입찰가) | 실제로 경매에 내는 금액 | **5,100** |
| **min_bsr / max_bsr** | 깎는 비율의 하한과 상한. a2admin에서 지면별로 정해요 | talk 상한 0.2125 |

**관계식**은 한 줄이면 돼요.

```
최종 입찰가 = eCPM × (1 − 수수료 − bsr)
            = 10,000 × (1 − 0.15 − 0.34) = 5,100
```

## 5. 상황에 따라 모델이 둘로 나뉘어요

어떤 광고 자리(slot)는 외부 광고 플랫폼이 자주 들어와서 경쟁이 붙고, 어떤 자리는 카카오 내부끼리만 경쟁해요. 그래서 계산 방식을 나눠요.

| | 경쟁 자리 | 비경쟁 자리 |
|---|---|---|
| 기준 | 어제 외부 플랫폼이 한 번이라도 낙찰한 자리 | 어제 카카오 내부만 낙찰한 자리 |
| 계산 방식 | **학습된 모델**이 넘어야 할 가격을 예측 | **규칙**: 모먼트 내부 2등 가격만큼만 냄 |
| 이유 | 외부 경쟁자의 가격을 맞혀야 하니까 | 외부 경쟁자가 없으니 내부 2등만 이기면 됨 |

- 서빙할 때는 이번 경매에 외부 플랫폼이 들어올지 미리 알 수 없어요. 그래서 "어제 기록"으로 자리를 구분해요. 피처 `n_other_dsp`가 0이면 비경쟁 자리예요.
- 이 모든 계산은 **모먼트 광고에만** 적용해요.
- 이번 과제(pb_* 경쟁 모델)는 왼쪽 열, **경쟁 자리의 학습 모델**이에요.

## 6. 경쟁 자리 모델은 어떻게 학습하나

### 무엇을 보고 무엇을 맞히나

- **보는 것 (입력)**
  - 유저 정보: 성별, 연령, 클릭 이력 등
  - 광고 자리 정보: 어느 slot인지, 몇 시인지
  - 이 광고의 eCPM
- **맞히는 것 (정답)**: 그 경매에서 **다른 플랫폼들이 부른 가격 중 최고가**(`ssp_close_price`)

예를 들어 "20대 남성, 톡 지면 상단, 저녁 8시, eCPM 10,000원짜리 광고"라는 상황을 보고 "이런 경매에서 다른 플랫폼들은 최고 5,100원쯤 불러"를 맞히는 문제예요.

### 학습 데이터는 어디서 오나

- 모먼트가 낸 입찰 기록과 카카오 SSP의 경매 결과 기록을 입찰 ID로 이어 붙여요. 세콰이어 플랫폼이 자동으로 만들어 줘요.
- 외부 플랫폼이 실제로 입찰한 경매만 학습에 써요. 경쟁자가 없으면 "넘어야 할 가격"이 없으니까요.
- 금액이 너무 작은 경매(지면별 하한 미만), 어뷰징이 의심되는 경매 등은 미리 걸러요.

### 얼마나 자주 학습하나

- **10분마다** 새로 쌓인 데이터로 조금씩 이어서 학습해요.
- 매번 처음부터 다시 학습하지 않고, 직전 모델을 그대로 이어받아 새 10분치만 반영해요.

### 오차는 어떻게 재나

- 예측 금액과 실제 금액을 **로그를 씌워서** 비교해요.
- 그래서 1,000원과 1,100원의 차이와, 10,000원과 11,000원의 차이를 비슷한 크기의 오차로 봐요. 금액 차이보다 **비율 차이**에 가깝게 보는 셈이에요.

## 7. 실제 입찰가가 나오기까지 (예시)

**상황**: 톡 지면, eCPM 10,000원, 수수료 15%

| 단계 | 계산 | 결과 |
|---|---|---|
| ① 수수료 떼기 | 10,000 × 0.85 | 쓸 수 있는 돈 **8,500** |
| ② 모델 예측 | "다른 플랫폼 최고가는 5,100원일 것" | **5,100** |
| ③ 비율로 환산 | dr = 5,100 / 8,500 → bsr = 0.85 × (1 − 0.6) | 깎는 비율 **0.34** |
| ④ 정책 상한 확인 | 톡의 상한은 0.2125 → 0.34는 초과 | 깎는 비율 **0.2125**로 제한 |
| ⑤ 최종 입찰가 | 10,000 × (1 − 0.15 − 0.2125) | **6,375원** |

- 모델은 "5,100원이면 이긴다"고 봤지만, 정책 상한 때문에 실제로는 6,375원을 내요.
- 반대로 예측가가 그 자리의 최저 입찰가(bidfloor)보다 낮으면, bidfloor까지만 깎아요.

## 8. 비경쟁 자리는 더 간단해요

외부 경쟁자가 없으니, **모먼트 내부 후보 중 2등만 이기면** 돼요.

**예시**: 수수료를 뗀 후보 금액이 8,500 / 6,800 / 3,000원일 때

- 1등 광고는 2등 가격인 **6,800원**만 내요.
- 학습 없이 정렬만 하면 되는 계산이에요.

## 9. 현재 운영에서 알아 둘 점

- **깎는 폭의 상한과 하한은 a2admin 한 곳에서만 관리해요.** 원래 torch-dnn에도 같은 제한이 중복돼 있었는데, 10/28 배포(ADRECBID-3064)로 제거됐어요.
- **지면별 상한은 정책값이라 모델 판단과 다를 수 있어요.** 예를 들어 pb_network는 2026년 7월 정책 변경으로 상한이 0.15까지 내려갔어요. 모델이 "많이 깎아도 된다"고 판단해도 실제 할인은 15%에서 멈춰요.
