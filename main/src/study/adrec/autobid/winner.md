# WINNER는 어떻게 동작하나 (현재 기준)

## 1. 한 줄 요약

WINNER는 **"이번 경매에서 이기려면 최소 얼마를 내야 하는지" 예측해서, 딱 그만큼만 입찰하게 해 주는 모델**이에요.

모먼트가 광고 하나를 내보내기로 정하면, 그 광고가 낼 수 있는 최대 금액(eCPM)이 정해져요. 하지만 최대 금액을 그대로 내면 손해일 때가 많아요. 경쟁자들이 그보다 훨씬 낮게 불렀다면, 그 경쟁자들보다 조금만 높게 내도 이길 수 있기 때문이에요. WINNER가 그 "조금만 높게"를 정해요.

### WINNER의 역할 범위: 무엇을 예측하고, 무엇을 계산하고, 무엇을 받아 쓰나

- WINNER는 "다른 플랫폼들의 최고 입찰가"를 예측하고(bid_price), 그 값을 깎는 비율(dr, bsr)로 환산하는 모듈이다.
- min_bsr과 max_bsr은 WINNER가 만들지 않는다. 사람이 정하는 정책값이고, WINNER의 bsr을 이 범위로 자른다.
- 최종 입찰가(sp)는 WINNER 다음 단계(a2 서빙)에서 계산한다.

| 값 | 만드는 곳 | 성격 |
|---|---|---|
| **bid_price** | **WINNER (모델 예측)** | 다른 플랫폼들의 최고 입찰가 **예측치**. WINNER에서 학습으로 배우는 유일한 값 |
| **dr** | WINNER (계산식) | bid_price를 비율로 환산한 값<br>`dr = max(bid_price, bidfloor) / eCPM'` |
| **bsr** | WINNER (계산식) | dr을 수수료 단위로 환산한 값<br>`bsr = (1 − ca − cd) × (1 − dr)` |
| min_bsr / max_bsr | a2admin, SCM config (사람이 설정) | bsr의 정책 상하한 |
| sp (최종 입찰가) | a2 서빙 | `sp = eCPM × (1 − ca − cd − bsr)` |

※ `eCPM' = eCPM × (1 − ca − cd)`: 수수료를 뺀 금액

```
bid_price  ← 학습으로 예측 (유일하게 배우는 값)
   ↓ 고정 수식: dr = max(bid_price, bidfloor) / eCPM'
dr
   ↓ 고정 수식: bsr = (1 − ca − cd) × (1 − dr)
bsr
```

> **주의**: `bid_price`는 이름 때문에 실제 입찰가로 오해하기 쉽다. 하지만 **WINNER가 예측한 "넘어야 할 가격"**이다. SSP에 실제로 제출하는 금액은 정책 clip을 거친 **sp**이고, 두 값은 다를 수 있다. 7절 예시에서 bid_price는 5,100이고 sp는 6,375다.

출력값이 만들어지는 과정과 상하한의 출처는 10절에서 자세히 다룬다. 용어는 4절, 계산 예시는 7절, 비경쟁 slot은 8절, 운영 이력은 9절을 참고한다.

## 2. 비유로 이해하기

중고 경매에 참여한다고 생각해 보면 쉬워요.

- 나는 이 물건에 **최대 10,000원**까지 낼 의향이 있어요. → **eCPM**
- 다른 참가자들 중 가장 높게 부른 사람이 **5,100원**을 불렀어요. → **넘어야 할 가격** (WINNER가 예측하는 값)
- 그러면 나는 10,000원이 아니라 **5,100원 남짓**만 불러도 이겨요. → **최종 입찰가**
- 아낀 4,900원이 광고주의 비용 절감이에요.

문제는 **다른 참가자들이 얼마를 부를지 미리 알 수 없다**는 거예요. 그래서 과거 경매 기록을 보고 예측하는 모델이 필요하고, 그게 WINNER예요.

> 위키에는 이 "넘어야 할 가격"이 "Winning Price = XMAS 기준 타 DSP의 1등 가격"으로 적혀 있어요. 풀어 쓰면 **"카카오 SSP 경매에서 모먼트를 뺀 다른 광고 플랫폼들이 부른 가격 중 가장 높은 값"**이에요.

## 3. 전체 흐름에서 어디에 있나

```
① 모먼트 안에서 광고 후보들 비교 (eCPM으로 줄 세우기)
② 1등 광고 선정 → 이 광고의 최대 금액 = eCPM
③ WINNER: "얼마나 깎아도 이길까?" 결정        ← 여기
④ 최종 입찰가로 카카오 SSP(XMAS) 경매에 참가
⑤ 외부 광고 플랫폼들과 경쟁 → 가장 높은 쪽이 낙찰
```

WINNER는 **입찰가를 정하는 마지막 단계**예요.

## 4. 알아야 할 용어 (최소한만)

| 용어 | 쉬운 뜻 | 예시 (eCPM 10,000원) |
|---|---|---|
| **eCPM** | 이 광고가 낼 수 있는 최대 금액 | 10,000 |
| **수수료 (ca, cd)** | 대행사 몫(0% 또는 15%) + 모먼트 몫(기본 15%). 입찰 전에 먼저 떼요 | cd 15% → 1,500 |
| **eCPM'** | 수수료를 떼고 실제로 경매에 쓸 수 있는 돈 | 8,500 |
| **dr** (discount rate) | 쓸 수 있는 돈 중 실제로 내는 비율 | 5,100 / 8,500 = **0.6** |
| **bsr** (bid shading rate) | 원래 eCPM 대비 깎는 비율 | **0.34** (= 3,400 / 10,000) |
| **sp** (최종 입찰가) | 실제로 경매에 내는 금액 | **5,100** |
| **min_bsr / max_bsr** | 깎는 비율의 하한과 상한. a2admin에서 지면별로 정해요 | talk 상한 0.2125 |

**관계식**은 한 줄이면 돼요.

```
최종 입찰가 = eCPM × (1 − 수수료 − bsr)
            = 10,000 × (1 − 0.15 − 0.34) = 5,100
```

## 5. 상황에 따라 모델이 둘로 나뉘어요

어떤 광고 자리(slot)는 외부 광고 플랫폼이 자주 들어와서 경쟁이 붙고, 어떤 자리는 카카오 내부끼리만 경쟁해요. 그래서 계산 방식을 나눠요.

| | 경쟁 자리 | 비경쟁 자리 |
|---|---|---|
| 기준 | 어제 외부 플랫폼이 한 번이라도 낙찰한 자리 | 어제 카카오 내부만 낙찰한 자리 |
| 계산 방식 | **학습된 모델**이 넘어야 할 가격을 예측 | **규칙**: 모먼트 내부 2등 가격만큼만 냄 |
| 이유 | 외부 경쟁자의 가격을 맞혀야 하니까 | 외부 경쟁자가 없으니 내부 2등만 이기면 됨 |

- 서빙할 때는 이번 경매에 외부 플랫폼이 들어올지 미리 알 수 없어요. 그래서 "어제 기록"으로 자리를 구분해요. 피처 `n_other_dsp`가 0이면 비경쟁 자리예요.
- 이 모든 계산은 **모먼트 광고에만** 적용해요.
- 이번 과제(pb_* 경쟁 모델)는 왼쪽 열, **경쟁 자리의 학습 모델**이에요.

## 6. 경쟁 자리 모델은 어떻게 학습하나

### 무엇을 보고 무엇을 맞히나

- **보는 것 (입력)**
  - 유저 정보: 성별, 연령, 클릭 이력 등
  - 광고 자리 정보: 어느 slot인지, 몇 시인지
  - 이 광고의 eCPM
- **맞히는 것 (정답)**: 그 경매에서 **다른 플랫폼들이 부른 가격 중 최고가**(`ssp_close_price`)

예를 들어 "20대 남성, 톡 지면 상단, 저녁 8시, eCPM 10,000원짜리 광고"라는 상황을 보고 "이런 경매에서 다른 플랫폼들은 최고 5,100원쯤 불러"를 맞히는 문제예요.

### 학습 데이터는 어디서 오나

- 모먼트가 낸 입찰 기록과 카카오 SSP의 경매 결과 기록을 입찰 ID로 이어 붙여요. 세콰이어 플랫폼이 자동으로 만들어 줘요.
- 외부 플랫폼이 실제로 입찰한 경매만 학습에 써요. 경쟁자가 없으면 "넘어야 할 가격"이 없으니까요.
- 금액이 너무 작은 경매(지면별 하한 미만), 어뷰징이 의심되는 경매 등은 미리 걸러요.

### 얼마나 자주 학습하나

- **10분마다** 새로 쌓인 데이터로 조금씩 이어서 학습해요.
- 매번 처음부터 다시 학습하지 않고, 직전 모델을 그대로 이어받아 새 10분치만 반영해요.

### 오차는 어떻게 재나

- 예측 금액과 실제 금액을 **로그를 씌워서** 비교해요.
- 그래서 1,000원과 1,100원의 차이와, 10,000원과 11,000원의 차이를 비슷한 크기의 오차로 봐요. 금액 차이보다 **비율 차이**에 가깝게 보는 셈이에요.

## 7. 실제 입찰가가 나오기까지 (예시)

**상황**: 톡 지면, eCPM 10,000원, 수수료 15%

| 단계 | 계산 | 결과 |
|---|---|---|
| ① 수수료 떼기 | 10,000 × 0.85 | 쓸 수 있는 돈 **8,500** |
| ② 모델 예측 | "다른 플랫폼 최고가는 5,100원일 것" | **5,100** |
| ③ 비율로 환산 | dr = 5,100 / 8,500 → bsr = 0.85 × (1 − 0.6) | 깎는 비율 **0.34** |
| ④ 정책 상한 확인 | 톡의 상한은 0.2125 → 0.34는 초과 | 깎는 비율 **0.2125**로 제한 |
| ⑤ 최종 입찰가 | 10,000 × (1 − 0.15 − 0.2125) | **6,375원** |

- 모델은 "5,100원이면 이긴다"고 봤지만, 정책 상한 때문에 실제로는 6,375원을 내요.
- 반대로 예측가가 그 자리의 최저 입찰가(bidfloor)보다 낮으면, bidfloor까지만 깎아요.

## 8. 비경쟁 자리는 더 간단해요

외부 경쟁자가 없으니, **모먼트 내부 후보 중 2등만 이기면** 돼요.

**예시**: 수수료를 뗀 후보 금액이 8,500 / 6,800 / 3,000원일 때

- 1등 광고는 2등 가격인 **6,800원**만 내요.
- 학습 없이 정렬만 하면 되는 계산이에요.

### 외부 DSP가 없는데 왜 깎아야 하나?

위너를 "외부 DSP를 이기기 위한 모델"보다 **"최종 입찰가를 정하는 단계"**로 보면 이해가 쉬워요.

- 내부 지면 경매(XMAS)는 **부른 값을 그대로 내는 방식(FPA)**이에요. 경쟁자가 없어도 부른 만큼 다 내요.
- 위너가 없으면 1등 광고 A는 **8,500원**을 내고 낙찰해요.
- 하지만 A가 이겨야 할 상대는 **모먼트 안의 2등 후보 B(6,800원)**뿐이에요. 6,800원만 냈어도 이겼어요.
- 그래서 비경쟁 자리에서도 1등을 **2등 가격으로 SSP에 제출**해요.

### 경쟁 자리와 무엇이 다른가

| | 경쟁 자리 | 비경쟁 자리 |
|---|---|---|
| 넘어야 할 상대 | 외부 DSP 최고가 | 모먼트 내부 2등 후보 |
| 그 값을 아나? | 모름 → **모델로 예측** | 앎 → **그대로 사용** |
| 방식 | 학습 모델 (PP) | 규칙 (SCM, 내부 2등가) |

- 비경쟁 자리의 위너는 "학습하는 모델"이 아니라 **"내부 2등 가격으로 깎아 주는 계산기"**예요. 그래서 위키 표에서 비경쟁 모델(`dr_all_scm`)은 학습 데이터 칸이 비어 있어요.
- 결과는 경쟁 자리와 똑같이 dr과 bsr로 나오고, a2admin의 상하한 clip도 똑같이 적용돼요.

### 아낀 돈(차액)은 누구 몫인가

위너로 깎은 금액은 **광고주와 플랫폼이 나눠 가져요.** 위키 용어 정의 기준이에요.

- **msr (marginShareRate)**: 깎은 금액 중 **광고주에게 돌려주는** 비율이에요. 광고주가 실제로 내는 금액(과금액)이 줄어요.
- **sr (surplusRate)**: 깎은 금액 중 **광고추천의 마진으로 적립하는** 비율이에요. 위키 설명으로는 나중에 광고주 혜택에 전략적으로 쓰기 위한 적립금이에요.

그러니까 "차액을 플랫폼이 다 먹는다"가 아니라 **"광고주 할인과 플랫폼 마진으로 나눈다"**에 가까워요. 실제 비율과 정산 방식은 확인하지 못했어요.

### 알아 둘 점

- **"비경쟁"은 어제 기록 기준이에요.** 오늘 외부 DSP가 갑자기 들어오면, 내부 2등가로 깎은 입찰이 질 수 있어요.
- **내부 DSP는 모먼트만 있는 게 아니에요.** 비경쟁 자리 정의는 "모먼트·포카만 낙찰한 자리"인데, SCM은 모먼트 후보끼리만 비교해요. 통합캠페인(모먼트 2.0)이 들어오면 내부 DSP끼리 서로 경쟁하는 문제가 생겨서, 위키에 별도 과제(통합캠페인 비경쟁 슬롯 내부랭킹 대응)로 올라가 있어요.
- **bidfloor 처리는 확인하지 못했어요.** 내부 2등가가 bidfloor보다 낮을 때 어떻게 되는지는 SCM 코드에 없어서, a2 서빙 쪽에서 처리하는 것으로 보여요.

## 9. 현재 운영에서 알아 둘 점

- **깎는 폭의 상한과 하한은 a2admin 한 곳에서만 관리해요.** 원래 torch-dnn에도 같은 제한이 중복돼 있었는데, 10/28 배포(ADRECBID-3064)로 제거됐어요.
- **지면별 상한은 정책값이라 모델 판단과 다를 수 있어요.** 예를 들어 pb_network는 2026년 7월 정책 변경으로 상한이 0.15까지 내려갔어요. 모델이 "많이 깎아도 된다"고 판단해도 실제 할인은 15%에서 멈춰요.

## 10. WINNER 출력값은 누가 만드나

### 10.1 WINNER 출력이 만들어지는 과정

WINNER는 ONNX 파일 하나로 서빙되고, 한 번 호출하면 `pwr, dr, bsr, bid_price`를 함께 돌려준다. 다른 플랫폼의 가격을 예측하는 별도 모델은 없다. **예측(bid_price)과 비율 환산(dr, bsr)이 WINNER 안에서 이어서 일어난다.**

#### 경쟁 slot (PP 모델)

```
[WINNER 내부]
① 예측   bid_price = 네트워크가 예측한 다른 플랫폼들의 최고 입찰가   ← 학습으로 배우는 부분
② 환산   dr  = max(bid_price, bidfloor) / eCPM'                    ← 고정 계산식
③ 환산   bsr = (1 − ca − cd) × (1 − dr)                             ← 고정 계산식
         pwr = 1 (서빙에서는 자리 표시용 값)
```

- 학습 정답은 실제 경매의 다른 플랫폼 최고가(`ssp_close_price`)다. 모델은 ①의 bid_price가 이 값에 가까워지도록 학습한다.
- 코드: torch-dnn `models/model/wpcrossv2.py`의 `forward_train`

#### 비경쟁 slot (SCM)

- ①의 예측이 없다. 따라서 bid_price를 예측하지 않는다.
- 같은 요청 안의 **모먼트 내부 2등 가격**을 그대로 써서 dr을 계산한다. 이후 ③은 경쟁 slot과 같다.
- 코드: torch-dnn `models/model/scm.py`

### 10.2 min_bsr / max_bsr은 어디서 오나

**계산하는 모듈은 없다.** 정책 결정이나 실험 결과에 따라 사람이 정하는 운영값이고, 학습되지 않는다.

| slot | 설정 위치 | 적용 방식 |
